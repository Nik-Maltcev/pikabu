# Requirements Document

## Introduction

Фича «Категории бизнеса по ОКВЭД» расширяет процесс выбора категорий в BizMap. Вместо ручного поиска по списку пользователь вводит ОКВЭД-код или описание своей деятельности, а LLM подбирает 2–5 релевантных категорий из существующего пула (Pikabu, VC.ru). Пользователь может принять предложения, скорректировать выбор вручную, а также комбинировать несколько категорий для объединённого анализа.

## Glossary

- **Category_Suggester** — сервис (бэкенд), принимающий пользовательский ввод (ОКВЭД-код или текстовое описание) и возвращающий список рекомендованных категорий через LLM
- **Topic_Selector** — страница фронтенда (TopicSelector.vue), на которой пользователь выбирает категории для анализа
- **ОКВЭД-код** — код из Общероссийского классификатора видов экономической деятельности (например, «56.10» — рестораны)
- **Категория** — запись из таблицы Topic в БД (Pikabu-тема или VC.ru-подраздел), используемая как источник данных для анализа
- **Мульти-выбор** — режим, при котором пользователь выбирает несколько категорий одновременно для объединённого анализа
- **Analysis_Pipeline** — существующий пайплайн парсинга и LLM-анализа, обрабатывающий посты и комментарии из выбранных категорий

## Requirements

### Requirement 1: Ввод ОКВЭД-кода или описания деятельности

**User Story:** Как пользователь, я хочу ввести ОКВЭД-код или текстовое описание своей деятельности, чтобы система подобрала релевантные категории без ручного просмотра всего списка.

#### Acceptance Criteria

1. WHEN пользователь вводит строку в поле ввода ОКВЭД, THE Topic_Selector SHALL отобразить кнопку «Подобрать категории» после ввода минимум 2 символов
2. WHEN пользователь нажимает кнопку «Подобрать категории», THE Topic_Selector SHALL отправить запрос к Category_Suggester с введённым текстом
3. THE Category_Suggester SHALL принимать на вход строку длиной от 2 до 200 символов
4. IF введённая строка короче 2 символов или длиннее 200 символов, THEN THE Category_Suggester SHALL вернуть ошибку валидации с описанием допустимой длины

### Requirement 2: LLM-подбор релевантных категорий

**User Story:** Как пользователь, я хочу получить от ИИ список подходящих категорий на основе моего ОКВЭД-кода, чтобы анализ охватил наиболее релевантные данные.

#### Acceptance Criteria

1. WHEN Category_Suggester получает валидный ввод, THE Category_Suggester SHALL отправить запрос к LLM с пользовательским вводом и полным списком доступных категорий
2. THE Category_Suggester SHALL вернуть от 2 до 5 рекомендованных категорий из существующего пула Topic
3. THE Category_Suggester SHALL вернуть для каждой рекомендованной категории её topic_id, название и краткое обоснование релевантности (до 100 символов)
4. THE Category_Suggester SHALL возвращать результат в течение 10 секунд с момента получения запроса
5. IF LLM не может определить релевантные категории для данного ввода, THEN THE Category_Suggester SHALL вернуть пустой список с пояснительным сообщением
6. IF вызов LLM завершается ошибкой или таймаутом, THEN THE Category_Suggester SHALL вернуть ошибку с кодом 503 и предложить пользователю выбрать категории вручную

### Requirement 3: Отображение и принятие рекомендаций

**User Story:** Как пользователь, я хочу видеть рекомендации ИИ с обоснованием, чтобы осознанно выбрать подходящие категории.

#### Acceptance Criteria

1. WHEN Category_Suggester возвращает список рекомендаций, THE Topic_Selector SHALL отобразить каждую рекомендацию с названием категории и обоснованием
2. WHEN пользователь нажимает на рекомендованную категорию, THE Topic_Selector SHALL добавить её в список выбранных категорий
3. WHEN пользователь нажимает кнопку «Принять все», THE Topic_Selector SHALL добавить все рекомендованные категории в список выбранных
4. IF Category_Suggester возвращает пустой список, THEN THE Topic_Selector SHALL отобразить сообщение «Не удалось подобрать категории» и предложить ручной выбор

### Requirement 4: Мульти-выбор категорий

**User Story:** Как пользователь, я хочу выбрать несколько категорий одновременно, чтобы получить объединённый анализ по всем выбранным направлениям.

#### Acceptance Criteria

1. THE Topic_Selector SHALL позволять пользователю выбрать от 1 до 5 категорий одновременно
2. WHEN пользователь выбирает категорию, THE Topic_Selector SHALL добавить её в список выбранных и отобразить счётчик выбранных категорий
3. WHEN пользователь повторно нажимает на выбранную категорию, THE Topic_Selector SHALL удалить её из списка выбранных
4. IF пользователь пытается выбрать более 5 категорий, THEN THE Topic_Selector SHALL отобразить предупреждение «Максимум 5 категорий» и отклонить выбор
5. WHEN пользователь выбрал хотя бы одну категорию, THE Topic_Selector SHALL отобразить панель выбранных категорий с возможностью удаления каждой через кнопку «×»

### Requirement 5: Ручное добавление и удаление категорий

**User Story:** Как пользователь, я хочу вручную добавлять и удалять категории из выбора, чтобы скорректировать рекомендации ИИ под свои нужды.

#### Acceptance Criteria

1. WHILE рекомендации отображены на экране, THE Topic_Selector SHALL сохранять доступ к полному списку категорий для ручного добавления
2. WHEN пользователь выбирает категорию из полного списка, THE Topic_Selector SHALL добавить её в список выбранных наравне с рекомендованными
3. WHEN пользователь удаляет категорию из панели выбранных, THE Topic_Selector SHALL удалить её из списка и обновить счётчик

### Requirement 6: Запуск анализа по нескольким категориям

**User Story:** Как пользователь, я хочу запустить единый анализ по всем выбранным категориям, чтобы получить объединённый отчёт.

#### Acceptance Criteria

1. WHEN пользователь нажимает «Далее» с несколькими выбранными категориями, THE Topic_Selector SHALL передать список topic_id всех выбранных категорий в запрос на запуск анализа
2. WHEN Analysis_Pipeline получает запрос с несколькими topic_id, THE Analysis_Pipeline SHALL загрузить и объединить посты и комментарии из всех указанных категорий
3. THE Analysis_Pipeline SHALL включить кросс-платформенные дубликаты (find_duplicates_by_name) для каждой из выбранных категорий
4. THE Analysis_Pipeline SHALL сгенерировать единый отчёт, охватывающий данные из всех выбранных категорий
5. IF одна из выбранных категорий не содержит данных в БД, THEN THE Analysis_Pipeline SHALL продолжить анализ по остальным категориям и указать в отчёте, какие категории не содержали данных

### Requirement 7: Обратная совместимость с одиночным выбором

**User Story:** Как существующий пользователь, я хочу продолжать выбирать одну категорию как раньше, чтобы новый функционал не сломал привычный процесс.

#### Acceptance Criteria

1. THE Topic_Selector SHALL поддерживать выбор одной категории без обязательного использования ОКВЭД-ввода или мульти-выбора
2. WHEN пользователь выбирает единственную категорию и нажимает «Далее», THE Analysis_Pipeline SHALL обработать запрос идентично текущему поведению системы
3. THE API эндпоинт /api/analysis/start SHALL принимать как единичный topic_id (текущий формат), так и массив topic_ids (новый формат)
